#### 画地形逻辑

在 `update()` 第 4 步(zone labels 之前)插入 terrain 矩形绘制:

```ts
// 4) Terrain rectangles (bookshelves + tables + columns)
if (state.terrain && state.terrain.length > 0) {
  for (const t of state.terrain) {
    const sx = toX(t.x - t.w / 2);
    const sy = toY(t.z - t.d / 2);
    const sw = t.w * scale;
    const sh = t.d * scale;
    // 颜色按 kind 区分(迷宫感)
    const color = t.kind === 'shelf' ? '#3a4a52'
                : t.kind === 'table' ? '#5a4a3a'
                : '#6a6a6a';  // column
    ctx.fillStyle = color;
    ctx.fillRect(sx, sy, sw, sh);
    // 细描边强化"墙"感
    ctx.strokeStyle = 'rgba(0,0,0,0.4)';
    ctx.lineWidth = 0.5;
    ctx.strokeRect(sx, sy, sw, sh);
  }
}
```

#### #4 四人桌 2 电位 = 4 人用

当前每个 studyTable 有 2 个 outlet box(中线偏 x),各自独立 occupied 红/绿。用户语义:2 电位供 4 人共用,**桌上 4 座位都满才算占**;1-3 空位都算绿(可充)。

**数据层改动**:
- `outletPositions` 数组中,**每个 studyTable 的 2 个 outlet 合并成 1 个 "table-level" outlet**(中心点 = 桌中心 `(p.x, p.z)`,不是 2 个偏移点)
- 视觉层:2 个 mesh 仍画(桌面中线左右各一),但**两者共享同一个 occupied 状态**(同绿同红)
- 判定:桌前 4 椅都坐 NPC = 红;任意空椅 = 绿

**实施**:
- 在 `buildOneStudyTable` 内:
  - `outletPositions.push({ x: p.x, z: p.z, occupied: false })` — **一个 outlet per table**(不再 push 2 个偏移)
  - 仍创建 2 个 mesh(`sq1`, `sq2`),但 `outletMeshes` 里**两个 mesh 共用同一 index** — 即 `outletMeshes.push(sq1, sq2)` 但 `outletPositions` 只有 1 项。这破坏"index 同序"约束,需重新设计。
  
  **更干净的方案**:加一个 `outletMeshGroups: THREE.Mesh[][]`(每个 outlet 对应一个 mesh 数组,大多数是 `[mesh]`,studyTable 是 `[sq1, sq2]`)。`setOutletOccupied(index, occ)` 改成遍历 `outletMeshGroups[index]` 全切色。

```ts
const outletMeshGroups: THREE.Mesh[][] = [];

// studyTable 内:
outletPositions.push({ x: p.x, z: p.z, occupied: false });
const group: THREE.Mesh[] = [];
for (const ox of STUDY_OUTLET_OFFSETS) {
  const sq = new THREE.Mesh(studyOutletGeo, outletMatEmpty);
  sq.position.set(p.x + ox, tableH + 0.011, p.z);
  tableZone.add(sq);
  group.push(sq);
}
outletMeshGroups.push(group);

// 其他 outlet 类型(柱电位、端板、壁插):
outletMeshGroups.push([singleMesh]);  // 单元素数组
outletMeshGroups.push([]);  // 壁插无 mesh
```

`setOutletOccupied` / `randomizeOccupiedOutlets` 改成遍历 group:
```ts
function setOutletOccupied(index: number, occupied: boolean): void {
  if (index < 0 || index >= outletPositions.length) return;
  outletPositions[index].occupied = occupied;
  for (const m of outletMeshGroups[index]) {
    m.material = occupied ? outletMatOccupied : outletMatEmpty;
  }
```

## 10. 风险与决策点

### 10.1 startPercent=0.10 选方案 B(baseDrain 缩放)

理由:1% 电主题需要百分比显示低,但实际游戏时长不能短到 18 秒(jam 评审 30 秒淘汰就体验不到完整循环)。方案 B 让"百分比=显示数字,实际时长=180s 不变"。**David 实现时务必选 B**,Snake review 时确认 `baseDrain = startPercent / totalGameTimeS` 而非 `1/180`。

### 10.2 SharedState.nearOutlet 字段名一致性

Sam gtaPrompt 读 `state.nearOutlet`(boolean),David main.ts 写该字段。**Snake prep commit 时锁定字段名**(已在 §2 + §8.1 写明),Sam/David 都 pull 同一 stub,字段名零分歧。

### 10.3 outletMeshGroups 引用稳定性

`rebuildTableZone` 会清 `outletMeshes.length = 0`,新 `outletMeshGroups` 也需同样清空 + 重建。David 实现时注意 rebuild 路径同步(outletMeshes → outletMeshGroups 全替换)。

### 10.4 GTA prompt 与 phone HUD 视觉协调

左上 prompt 与右下 phone HUD 分占屏幕两角,不冲突。中下任务条在 `bottom:80px` 位于 phone HUD(chassis 高 540px + bottom 20px)上方,需 MCP 验证实际不挡 — 若挡调到 `bottom:600px` 或更高。

### 10.5 terrain 在 rebuildTableZone 后引用稳定?

terrain 是静态数组(书架+柱子+studyTable 位置),rebuildTableZone 只改 studyTable 行距 / 椅距 / 空位,不改 studyTable 数量与中心位置 → terrain 数组**不变**。但若 debug overlay 调 rowSpacing → studyTable x/z 中心变 → terrain 与视觉脱节。jam 期 debug 只用于开发,不影响玩家体验。PR #14 polish 时让 terrain 也跟随 rebuild 更新(留 backlog)。
